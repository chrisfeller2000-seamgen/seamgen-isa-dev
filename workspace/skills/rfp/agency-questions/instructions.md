# Questions for the agency's Q&A

## What this skill does

ISA writes the questions. `scripts/rfp-questions.mjs` does the rest:

- it gathers what the questions are written from;
- it gives the questions deadline from the RFP's key-dates note, the same one the calendar skill uses, and stops when the window has closed;
- it checks the questions, fills in the email template and saves the result as `agency-questions_<slug>.md` in the RFP's folder, so "what did we ask?" has an answer later.

**ISA never creates a Gmail draft and never sends this email.** It goes to the buyer, and a clumsy or early question to an agency contact can't be taken back. Whoever sends it pastes it into their own mail and addresses it themselves.

**Never write the email or the deadline line yourself.** Every reply with questions is the script's text, sent word for word: no outreach footer, no "generated by ISA" line, no Sales cc. If the script can't run, say so instead of writing the email.

**This email is external and formal.** It represents Seamgen to the buyer, and every bidder reads the agency's published answers.

## When to use it

When someone asks for Q&A or clarifying questions on an RFP Seamgen is pursuing, or asks to change questions already written. Many RFPs post no Q&A window; reaching out anyway gets our name in front of the buyer, as long as the answers can still shape the proposal.

An RFP marked "ask the agency first" in the Friday results needs one question answered before anyone decides to bid (`askTheAgency` in the inputs below). For that RFP, the email can be just that question, or that question first with a few others.

Not for no-bid RFPs.

## Step 1: gather the inputs

```
node scripts/rfp-questions.mjs --rfp <slug> --inputs
```

It prints:

- **`steps`**: what this RFP's inputs call for (record the deadline, ask about the incumbent, settle the blockers). Do each one.
- **`keyDates`**: the dates recorded from the documents, including "Questions due" and "Proposal due" when they were found.
- **`scoring`**, from the RFP's scoring notes:
  - `buyer`: what the agency uses today, what it wants, and how the evaluation favours us. `noIncumbentNamed: true` means the documents don't say who supports the current system, so ask.
  - `askTheAgency`: the question to send first, when there is one.
  - `questionsDeadline`: the deadline the scorer found, with its quote. The scorer can miss one, so check the documents too.
- **`results`**: the plain-language blockers and open questions from this week's results, or from the last run that scored the RFP.
- **`engineeringBrief`**: the "Ambiguities Requiring Clarification" section of the newest engineering brief, when one was written.
- **`savedQuestions`**: the questions given last time, if any.

Then read the documents (`documents.readAll`, or the router's `documents` by number). They are the source of truth: every question points back to a file and page, and the evaluation criteria come from them. Don't ask the person for anything ISA can read itself. If no documents are saved, follow `skills/rfp/document-fetch/instructions.md` first.

**Never invent** a deadline, contact, page number or requirement.

## Step 2: the questions deadline

If `keyDates` has no "Questions due", find the deadline in the documents (check any addendum too) and record it, so the calendar skill gives the same one:

```
node scripts/rfp-dates.mjs --rfp <slug> --merge <<'RFP_DATES_END'
{ "name": "<short RFP name>", "zone": "<agency zone>",
  "milestones": [ { "kind": "questions", "date": "<as printed>", "time": "<as printed>", "source": "file <n>, page <p>" } ] }
RFP_DATES_END
```

Add the proposal due date the same way if `keyDates` doesn't have it. Don't send that script's output: the questions script gives the deadline line. If the documents give no questions deadline, say so in `noDeadline` in step 4.

## Step 3: write the questions

**How many:** aim for 5–7. Write fewer only when the RFP leaves little real doubt, or for an "ask the agency first" RFP. If more than 8 survive the rules below, keep them and give every question a `group` header (Scope, Technical, Budget, Timeline); the script requires headers past 8 and refuses more than 15. Fold related questions into `sub` questions rather than cutting one that matters.

**What comes first.** When there are more candidates than room, keep them in this order:

1. the "ask the agency first" question, when there is one;
2. blockers and open questions only the agency can settle. A blocker only Seamgen can fix, such as a certification we lack, is not a question for the agency;
3. the engineering brief's ambiguities, merged with the others by topic. Where one overlaps another question, use the brief's wording, since it is sourced. Each distinct one affects timeline or price;
4. who supports the current system, when `noIncumbentNamed` is true;
5. where the RFP leaves real doubt: scope (what the agency provides and what the vendor produces), technical specifics (named platforms, integrations, hosting, data volume) and success criteria ("what would you build without constraints?"). An AI-forward RFP (AI, AEO/GEO, chatbots, ML, agentic work) gets at least one AI question.

Then apply every rule below, especially rule 8.

## Rules for questions in this email

1. **Answerable by the agency contact.** Ask concrete, procurement-appropriate things, not "what will the political dynamics look like?"
2. **Needed to shape the proposal.** If the RFP already answers it, don't ask. Evaluators notice sloppy questions.
3. **No assumptions that could offend.** "Is the incumbent being considered?" is fine. "Are you unhappy with the incumbent?" is not.
4. **Numbered, not bulleted**, so the agency can answer by number. The script numbers them.
5. **Grouped under headers when there are many** (more than 8).
6. **A page pointer, not a quote.** "The technical requirements starting on page 5" shows we read the RFP. The verbatim quotes belong in each question's `source`, never in the question. The script refuses a question that repeats its source's quote.
7. **Nothing internal reaches the agency:** no HigherGov or Drive link, no scores, gates, blockers or pursue tiers, and no line saying where we found the RFP. The script refuses them.
8. **Never ask a question that exposes a weakness or invites scrutiny.** Evaluators read every question, and once answered publicly so does every competitor. Before each one ask: does the answer change what we do, or does asking change what they think of us? If it's the second, cut it. Marianne cut two from Suwannee 26/27-002:
   - how a "zero-error rate" migration standard would be measured. "We are professionals so of course we ingest 100% correct." It reads as doubt about a competence the work plan should show;
   - whether the AI-use disclosure covers proposal tooling. That line sat inside the 50-point Work Plan criterion, so asking drew evaluators' attention to our AI use for nothing.

   **The boundary:** a question about a requirement we must price or design against is fair even when the answer might be unwelcome.
9. **Hard to answer evasively.**
   - "Is there a budget?" becomes "Has the District established a budget or not-to-exceed amount? If so, please provide the range. If not, please confirm that no budget has been established."
   - "Is there an existing vendor?" becomes "Who is the vendor currently supporting…?", which returns a name.
10. **Read the evaluation criteria before finishing the list.** The answers are published, so a question can also show the right approach. Suwannee put 50 of 100 points on Work Plan & Approach, starting with "Understanding of the District's needs", so Marianne added a question about spending time with District staff to learn the workflow as it is actually done.
11. **Ask an awkward fit question plainly.** When the scoring leaves real doubt that we are the right kind of firm (a product buy, or proof asked of a product vendor), describe what we are and ask. Marianne's Suwannee question: "we have built ArcGIS functionality before, but Seamgen is a bespoke software development company… specializing in workflow automation, agentic workflows and system integration as a layer on top of systems such as ArcGIS, rather than in implementing ArcGIS itself. Does it make sense for a firm of that profile to submit an offer?" Describe the firm honestly; never overstate it to steer the answer.

## Step 4: run the script and send its text

```
node scripts/rfp-questions.mjs --rfp <slug> <<'RFP_QUESTIONS_END'
{ "name": "<full RFP name as printed>", "number": "<RFP number>", "agency": "<agency as printed>",
  "contact": { "name": "<as printed>", "honorific": "<Mr./Ms./Dr., only when the RFP prints it>", "email": "...", "phone": "...", "source": "file <n>, page <p> (no quote)" },
  "submission": "<how questions must be submitted: email, portal form, required subject line>", "portalOnly": false,
  "questions": [
    { "text": "<the question as the agency reads it>", "sub": ["<optional sub-question>"], "group": "<header, past 8 questions>",
      "source": "file <n>, page <p>: \"<verbatim RFP text>\" (or: RFP is silent; nearest context <section>)",
      "resolves": "<the blocker or open question it settles, in plain words, when it does>" }
  ] }
RFP_QUESTIONS_END
```

- **`noDeadline`**: add it only when the documents give no questions deadline: `"noDeadline": "The documents give no questions deadline."` (or why it couldn't be confirmed, such as documents not downloaded).
- **`sender`**: leave it out unless the person said who will send it, then fill it in from what they said. Otherwise the signature stays a placeholder, because no single person sends these.
- **`contact`**: leave it out when the documents name nobody; the script says to find out who takes questions. Never guess Mr. or Ms. from a first name.

What it prints:

- **The text between the lines:** send it word for word. It has the deadline line, who to send it to and how, the sources (for the team to check, never for the agency), and the email in a code block. When questions were saved before, it ends with what changed.
- **"Nothing was saved. Fix these…":** fix each problem and run it again. Don't send anything yet.
- **"Nothing was saved. The questions window closed…"** (or proposals are due, or due too soon): tell the person, and ask whether they still want the questions, for example to prepare for an interview. Run it again with `--anyway` only after a clear yes.

## Changing questions already written

For "add a question about hosting", "drop question 3" or a new addendum: run `node scripts/rfp-questions.mjs --rfp <slug> --show`, take its `input`, make the change, and run step 4 with the changed input. The script lists what was added and dropped. "What did we ask?" and the agency's answers are handled by the router from the saved file, without this skill.

## Katie's Rancho Palos Verdes questions (June 22, 2026)

The template is Katie's email to the City of Rancho Palos Verdes for its Recreation Management Software Platform RFP. Her questions show the tone: a colleague asking what the work needs, not someone begging for scraps. Her list predates the 5–7 guideline; twelve questions today would be grouped under headers.

1. Please share the link to the existing website
2. What are the 3 biggest pain points of the current website?
3. Aside from the technical requirements listed starting on page 5, are there any other UI enhancements you are looking for in the recreation management software platform?
4. As the current software provider, is ActiveNet being considered for the new recreation management software platform?
5. If you could design the ideal version of your website without limitations, what would it look like in terms of design, functionality, and user experience?
6. What manual workflows are you looking to make more efficient?
7. To increase resident participation in recreation programming, are there specific demographic groups you would like to target with the new recreation management platform?
8. Have you considered a chat bot to increase search functionality for the public user? Would this be something that you are interested in?
9. Does payment and billing functionality need to integrate with a Kiosk solution?
   - Does the City have a preferred existing payment and billing hardware provider that the contractor must integrate with, or should hardware ecosystem be suggested as part of the solution?
10. Does the contractor need to provide iOS and Android Apps that are published to the Apple App Store and Google Play, or just 100% functional parity (aka run in their web browser on the mobile device)?
11. Do you have a ballpark figure or a maximum budget in mind for this project so I can ensure our proposal meets your expectations?
12. Will you share the comprehensive Q&A submitted by all prospective bidders on the RFP portal?

What to keep from it:

- Question 3 points at a page, which shows the RFP was read.
- Question 9 keeps a related point together as a sub-question.
- Question 11 turns "what's your budget?" into help: "so I can ensure our proposal meets your expectations".
- Question 12 asks for the public Q&A, which shows what competitors asked and where the agency is getting pushback.

## Notes and edit history

**v2.0 — November 24, 2026.** `scripts/rfp-questions.mjs` now does the parts that need no judgment:

- it gathers the inputs (`--inputs`): the scoring notes kept with the RFP, the blockers from the results or the audit, the engineering brief's ambiguities and the key dates;
- it gives the deadline line and stops when the window has closed;
- it fills in the template, numbering and headers;
- it refuses internal words, pasted quotes, unsourced questions and long ungrouped lists;
- it saves the questions for "what did we ask?" and later edits.

The question count now has a rule for when the sources add up to more than 8. Katie's example is now her questions only. The router answers questions about the agency's answers and about what was asked, instead of writing new questions. The edit history before this version is in Git.

**v1.7 and earlier (July–November 2026).** Katie's Rancho Palos Verdes email became the template in v1.0, and Marianne's Suwannee review added rules 8–11 in v1.5. From v1.6 the email is given as text to copy, with no Gmail draft and no named signer. In v1.7 the deadline began coming from the key-dates note.

**How to edit this skill:** change the text, bump the version and add a note here. Change the email template in `scripts/rfp-questions.mjs` (`renderEmail`), and its test in `devtools/rfp-questions.test.mjs`.
