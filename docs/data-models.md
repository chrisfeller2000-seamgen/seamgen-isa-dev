# Runtime data contracts

This repo has no database schema or migration system. The live jobs use files and provider records as data contracts; most such files are intentionally absent from Git.

| Contract | Runtime location / writer | Important fields or rule |
| --- | --- | --- |
| RFP candidate | `RFP-pipeline/candidates/<slug>/candidate.md`, written/updated by `weekly-rfp-pursue-decision.mjs` | Provenance (`opp_key`, `version_key`, `captured_date`), source/agency/deadline/value, preliminary and final scores, `scoring_confidence`, `qualification_status`, `document_status`. Metadata is provisional. |
| Solicitation resources and manifest | `RFPs/<stage>/<slug>/resources/`, written by the RFP document flow | Saved document paths, role/required flag, download and extraction outcome, completeness. Each row's `source` is `highergov` or `posting`. A posting row also has `source_host`, `fetched_from` (origin and path, never a query string), `match_required` and `match` (`matched`/`unmatched`; unmatched rows are never scored). The top-level `posting` is the posting attempt's outcome. Full-text requires an extracted solicitation and no known missing required scoring document. |
| Secondary deadline assessment | `reports/new-rfp-qualification/*-secondary-fulltext.json`, written by the secondary scorer | `timeline.status`, `due`, `time`, `timeZone`, `source`, `evidence`, `supersessions`, assessment/date-count fields, finite-or-null `days`, and tri-state `pass`. Only verified deadlines pass/fail the timeline gate; unresolved deadlines give `gate1: null` and `fulltext_score: null`, not an automatic pass. Rows without a readable solicitation have `recommendation: Needs documents`, `fulltext_score: null`, `categories: null`, null gates, and a plain `fetchReason`; `summary.needsDocuments` counts them. |
| Weekly RFP audit | `reports/new-rfp-qualification/audit/<run date>.jsonl`, appended by `rfp-audit.mjs` during the weekly run | One line per listing pulled, `schemaVersion: 1`: report entries, plus intake drops and duplicates with `outcome.tier: "skipped"`. Each line has:<ul><li>`run`;</li><li>`rfp` (HigherGov `versionKey`/`oppKey`, `listingText`);</li><li>`outcome` (as reported, plus plain `decision` and `why`, need, budget, due, blockers);</li><li>`listing` and `fullText` scoring (gates with reasons, categories, error, `attempts`, `seconds`, model, prompt and skill hashes, the model's answer with quotes cut to 300 characters, and `rejections`: each rejected answer with its try and reason);</li><li>`documents` (completeness reasons, names, read status and `source` only, plus `posting`: the agency-posting attempt's site and outcome, no URLs).</li></ul>Never deleted by the job; a same-day re-run writes `-2`. |
| Company facts | `resources/proposal-sources/company-facts.json` on the VM, maintained by hand outside Git; read by `loadScoringContext()` | `version: 1` and `facts[]`. Each fact has an `id`, a `type` (registration, certification, insurance, reference) and a `status`. Anything not `unconfirmed` also needs `verifiedBy`, `verifiedDate` and `source`. Unknown fields are rejected and a malformed file stops scoring. See [company facts](domains/rfp/company-facts.md). |
| HigherGov intake state | `RFP-pipeline/state.json` and `seen.csv` | Watermark/seen keys avoid duplicate intake. Do not reset or advance them during a local test. |
| Sales job output/state | `reports/` under the live workspace | Mail-sync processed IDs and last success, plus generated reports. These can contain private business data and are not Git source. |
| OpenClaw state | VM's OpenClaw state directory or ignored local `.isa-local/` | Sessions, configuration, auth, and scheduler payloads are runtime state, not imported by `devtools/live-files.json`. |

`workspace/scripts/weekly-rfp-pursue-decision.mjs` currently parses YAML-like candidate frontmatter itself. If a field or status changes, update the writer, reader, manifest handling, and fixtures together; do not silently reinterpret older candidates. The [RFP domain](domains/rfp/README.md) owns qualification meaning. See [security](security.md) before inspecting or copying real runtime files.
