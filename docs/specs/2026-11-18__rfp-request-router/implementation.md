# Implementation record: the RFP request router

## Why

ISA chose RFP skills by reading the request against instructions in `AGENTS.md`. In local tests on November 18, 2026 that worked when a request named an RFP task, but not for open wording. On "Yes, move Laguna Beach" and "write the email that goes with it", ISA acted from memory, made up commands, wrote the agency email freehand, and once said an RFP had moved without running anything. Moving the RFP rules into an index that `AGENTS.md` points to (the `exp/rfp-router` experiment) helped the calendar case but not these.

The user asked for two things: requests in a standard form where possible, and better matching where they aren't. They also asked that OpenClaw's own skill format, the Skill Workshop and the VM settings stay untouched, because other people work on ISA.

## What changed

- **Per-skill folders.** The 11 chat RFP skills moved to `workspace/skills/rfp/<skill>/instructions.md`:
  - engineering-brief, capability-check, agency-questions, calendar-dates;
  - submission-checklist, proposal-deck, materials-request, moonshot;
  - submission-email, document-refresh, document-fetch.

  Each header gained `label`, `command`, `phase`, `when` and `asks` (the ways people ask for it). Several `asks` phrasings come from real chats on the VM (July–October 2026), read-only and with names changed. Nothing is named `SKILL.md`.
- **Request router** (`workspace/scripts/rfp-route.mjs`). It reads the message and returns one JSON decision: `run-skill`, `ask-move`, `ask-which-rfp`, `ask-which-phase`, `move`, `offer`, `list`, `answer`, `share-documents`, `rescore`, `retired`, `needs-context` or `none`.
  - **Input it understands:** the `rfp <command> <rfp>` form, Telegram button data (`callback_data: rfp:…`), and free text.
  - **Phase rules:** applied in code.
  - **Questions:** written out ready to send, with numbered choices. Each choice carries the exact router call (`route`) to run when the person replies with a number, "yes", "no" or "keep it".
  - **Read-only:** it never writes anything.
  - **Messages arrive on standard input.** ISA passes the person's message through a quoted heredoc (`<<'RFP_MESSAGE_END'`), never inside quotes on the command line, where `"`, `$(` or backticks from a group member would run as shell commands. Arguments are only for the router's own `route` commands, which hold nothing but command words and RFP slugs.
- **After a move** (`workspace/scripts/rfp-stage.mjs`), the move script itself prints the new phase's skills, after a line telling ISA to pass them on word for word because the person can't see command output. In one round, ISA twice sent the router's pre-written "Moved …" text without running the move. Since then, the skill list exists only in the move's output. In a later round, ISA sometimes sent only "Which one?", which the relay line fixed.
- **`workspace/AGENTS.md`:**
  - The RFP section says: run the router on every RFP message, including replies and taps, and do what it decides.
  - The hard rules and the Friday-offer line stay.
  - The Gmail footer rule gained one line, sending agency emails about an RFP or proposal through the router. In one test, ISA followed the footer rule into a freehand email.
  - The file went from 19,747 characters to about 12,900.
- **`workspace/skills/rfp/INDEX.md`:**
  - It holds the RFP procedures that were in `AGENTS.md`, what to do for each router decision, and the command list.
  - Its skill table is generated by `npm run rfp:index` (`devtools/rfp-index.mjs`).
- **Command sheet** for the sales group: `docs/domains/rfp/commands.md`.
- **Not changed:**
  - **The three scoring-prompt skills.** Their text still names some skills by old file paths; editing them changes Friday scoring.
  - **The pursue, no-bid and retired meeting-brief skills.** They stay where they are.
  - **Telegram buttons.** That's phase 2 of the plan, which the user deferred.

## Local ISA runs, November 18

**How they ran:**
- **Model:** `openai/gpt-5.4-mini` with tools off.
- **ISA's side:** it wrote each command it would run.
- **Tester's side:** the router ran for real against the fixture workspace, and other commands got realistic output.
- **Not checked:** the live model and tool use.

| Request | Router first | Result |
| --- | --- | --- |
| "Yes, move Pasco County" (Friday offer) | 3 of 3 | 3 of 3 ran the move, then passed on the Phase 2 skill list it printed |
| "What can you do for the Laguna Beach RFP?" | 3 of 3 | 3 of 3 listed all four Phase 2 skills with commands |
| Checklist (Phase 3) for an RFP in Phase 2, then "No, keep it where it is" | 3 of 3 | 3 of 3 asked first; 3 of 3 then ran the `--stay` route and opened the checklist skill |
| Same, then "1" | 3 of 3 | 3 of 3 ran the move from choice 1 |
| Engineering brief for an RFP in Phase 2 | 3 of 3 | 3 of 3 opened the skill with no move question |
| "rfp brief laguna-beach-website-redesign" | 3 of 3 | 3 of 3 opened the skill |
| Calendar dates for an RFP in Phase 1, then "No, leave it in Phase 1" | 3 of 3 | 3 of 3 asked first; 2 of 3 then ran the `--stay` route, 1 stalled |
| "Can you write the email that goes with it?" (proposal) | 1 of 3, then 5 of 5 after naming proposal emails in `AGENTS.md` | 5 of 5 opened the submission-email skill and checked whether email is allowed |

A final round used the standard-input form and the relay line, with two runs of each request (five for the Friday reply). ISA ran the router first in all 15 runs. The Friday reply ran the move and passed on the full skill list in 5 of 5. The other requests behaved as in the table, including the submission email (2 of 2 to its skill).

Before the router (the `exp/rfp-router` experiment), the same requests reached the right step in roughly 0–75% of runs. The weakest cases were the Friday reply (6 of 12 read the index first) and the submission email (2 of 4).

**Seen in the runs:**
- **Missing documents:** when the fixture RFP had no documents, ISA asked for the RFP text instead of guessing. That's the right behavior.
- **Examples read as rules:** the submission-email skill uses Yonkers as its example of a portal-only RFP. With a test RFP also named Yonkers, some runs repeated that example as this RFP's rule without opening the documents. The skill's examples could be marked more clearly as examples.
